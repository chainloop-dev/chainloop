## Language

- **Harness**: a coding agent that Trace records, for example Claude Code, Cursor, OpenCode, Pi, or Codex. _Avoid_: "agent" for the product, because the agent is also the model that follows the capture instruction.
- **Provider**: the Trace integration for one harness: its hooks, its transcript parser, and its finders. The provider ID is the harness name in lower case, for example `pi`.
- **Session material**: the AI coding session evidence of one session. It holds the transcript, the file changes, and the spec list. It holds references to spec materials, not their content.
- **Spec source**: an input that sets or explains the task of a session, for example a ticket, a document, an approved plan, or an image. _Avoid_: "the prompt". The user's request prompt is not a spec source, because the transcript holds it.
- **Capture**: the agent writes a spec source into the session spec folder. The CLI captures skills and pasted images itself.
- **Kind** and **Role**: the kind is the format of a spec source (`ticket`, `document`, `image`, `text`, `skill`). The role is its purpose (`task`, `spec`, `plan`, `reference`). _Avoid_: a new kind for a purpose, for example a `plan` kind.
- **Spec entry**: one item of the spec list in the session material. It points to a spec material by digest.
- **Pointer**: a copy of a spec source in the transcript that the CLI replaced with the `chainloop.replaced` marker and the digest of the material. _Avoid_: "placeholder" for this, although the file name of Spec issue-3556 uses it.
- **Placeholder**: the fixed line that the agent writes as the body of a local-file capture. The push replaces it with the file content.
- **Pasted image**: an image the user pasted into the harness. The CLI captures it from the transcript as "Pasted image N".
- **Local mode**: Trace stores sessions on disk with no control plane, set with `traceStorage: LOCAL`. _Avoid_: "offline" (the model is online), "export" (exporting a recorded session is a separate, future feature), `requireTrace` and `localTrace` (use `traceRequired`).
- **Trace directory**: the directory where Trace keeps all its state for a checkout, set with `tracePath`. Default `.git/chainloop-trace`.
- **Net contribution**: the lines a session added that no later commit replaced. It is the AI and human split that Trace reports.
- **Ledger**: the AI line ledger, the fingerprints of the lines that agent edits wrote.
- **Join**: a commit with no session that replaces lines of a session joins that session as human work.
- **Feature table**: the table of the Trace README that marks each feature per harness. The end-to-end suite reads it as the expected result. A **cell** is one harness, model, and feature.

## Current decisions

### Who decides what the spec is
The agent, told by an instruction at session start. For skills, the CLI makes the entries ([issue-3540 D-002](../specs/issue-3540-trace-skills-used.md)), and for pasted images the CLI captures them ([issue-3569 D-001](../specs/issue-3569-pasted-image-pointers.md)).
- Why: Only the agent knows which input sets the task.
- Rejected: extraction from the transcript by the CLI.
- Source: [issue-3495-session-spec-capture D-001](../specs/issue-3495-session-spec-capture.md)
- Code: verified: the session-start hook gives the capture instruction (`app/cli/pkg/action/trace_spec.go`)

### Where the spec content goes
One EVIDENCE material per source, with references in the session material.
- Why: One copy in the CAS for all sessions, and each source is verifiable alone.
- Rejected: text inside the session material.
- Source: [issue-3495-session-spec-capture D-002](../specs/issue-3495-session-spec-capture.md)
- Code: verified: `trace_spec_materials.go` stores each capture as its own material

### Folder location
A folder in the working tree that ignores itself.
- Why: The agent writes there with no permission prompt.
- Rejected: a folder in the git directory.
- Source: [issue-3495-session-spec-capture D-004](../specs/issue-3495-session-spec-capture.md)
- Code: verified: `.chainloop/specs/<session>` with a `*` `.gitignore` (`internal/trace/spec/spec.go`)

### When the session folder is deleted
When the session ends.
- Why: Each push of a session must hold its spec.
- Rejected: delete after each push.
- Source: [issue-3495-session-spec-capture D-009](../specs/issue-3495-session-spec-capture.md)
- Code: verified: the session-end hook removes the folder

### Images
A file image is copied byte for byte. A pasted image becomes a description that the agent writes. Partly replaced by [issue-3515 D-009](../specs/issue-3515-spec-capture-during-session.md) and [issue-3569 D-001](../specs/issue-3569-pasted-image-pointers.md): the agent does not describe a pasted image, and the CLI saves it.
- Why: The agent cannot recover the bytes of a pasted image.
- Source: [issue-3495-session-spec-capture D-010](../specs/issue-3495-session-spec-capture.md)
- Code: verified for file images. Pasted images are saved by the CLI from the transcript ([issue-3569 D-001](../specs/issue-3569-pasted-image-pointers.md)), not described by the agent

### Redaction on later pushes
Keep the redacted copy of each file, keyed by the digest of the source, and reuse it.
- Why: Redaction is expensive.
- Rejected: scan again on each push.
- Source: [issue-3495-session-spec-capture D-011](../specs/issue-3495-session-spec-capture.md)
- Code: verified: `specRedactor` in `trace_spec_materials.go`

### Capture of a user prompt
Do not capture the user's request prompt. Capture a spec that the user pastes.
- Why: The transcript holds the prompt.
- Rejected: keep it and label it "prompt".
- Source: [issue-3515-spec-capture-during-session D-001](../specs/issue-3515-spec-capture-during-session.md)
- Code: verified: `trace_spec.go`

### How specs are found after session start
A short reminder at each user prompt.
- Why: It keeps the agent as the decider and covers resumed sessions.
- Rejected: a general capture rule, and a hook that watches spec paths.
- Source: [issue-3515-spec-capture-during-session D-002](../specs/issue-3515-spec-capture-during-session.md)
- Code: verified, with five cases (`trace_agent_hook.go`)

### Spec file limit
25 files. Never drop a file that an earlier push recorded.
- Why: Long sessions get more specs, and the oldest are the start sources.
- Rejected: keep the newest files.
- Source: [issue-3515-spec-capture-during-session D-005](../specs/issue-3515-spec-capture-during-session.md)
- Code: verified: `spec.MaxEntries`. Gap: local mode never saves the list of recorded files, so an overwritten start file can drop (`trace_local_store.go`)
